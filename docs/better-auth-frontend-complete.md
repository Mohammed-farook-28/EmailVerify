## Implementation Details

### 1. Auth Client Setup (`auth-client.ts`)

```typescript
import { createAuthClient } from "better-auth/react";
import { emailOTPClient } from "better-auth/client/plugins";

export const authClient = createAuthClient({
  baseURL: process.env.NEXT_PUBLIC_API_URL,
  plugins: [emailOTPClient()],
});

export const {
  signIn,
  signUp,
  signOut,
  useSession,
} = authClient;
```

**Features:**
- Email OTP plugin enabled
- Exports commonly used hooks
- Type-safe client methods

### 2. Auth Provider (`auth-provider.tsx`)

**Changes:**
- Replaced TanStack Query-based session fetch with Better Auth's `useSession` hook
- Maps Better Auth user to application's User type
- Maintains backward compatibility with existing `useAuth()` hook
- Handles custom fields (firstName, lastName, language, etc.)

**Session Management:**
- Better Auth handles session state automatically
- No manual cache invalidation needed
- Session persists across page reloads
- 30-day expiration (configured in backend)

### 3. Sign-Up Flow (`sign-up/page.tsx`)

**New Flow:**
1. User enters: Email, First Name, Last Name
2. Click "Sign Up" → Sends OTP to email via `authClient.emailOtp.sendVerificationOtp()`
3. Stores signup data in `sessionStorage`
4. Redirects to `/auth/verify-email?email={email}`
5. User enters 6-digit code
6. Verified → Account created → Redirected to dashboard

**UI Changes:**
- ❌ Removed password field
- ✅ Added info text: "You'll receive a 6-digit verification code via email"
- ✅ Updated Google OAuth to use Better Auth's `signIn.social()`

### 4. Sign-In Flow (`sign-in/page.tsx`)

**New Flow:**
1. User enters: Email only
2. Click "Sign In" → Sends OTP to email
3. Redirects to `/auth/verify-email?email={email}&type=sign-in`
4. User enters 6-digit code
5. Verified → Logged in → Redirected to dashboard

**UI Changes:**
- ❌ Removed password field
- ❌ Removed "Reset Password?" link
- ✅ Added info text: "We'll send a 6-digit verification code to your email"
- ✅ Updated Google OAuth button

### 5. Verify Email (`verify-email/page.tsx`)

**Updated to handle:**
- Sign-up verification (creates new account)
- Sign-in verification (logs in existing user)
- Resend OTP functionality
- Error handling (invalid code, expired code, etc.)

**Methods:**
- `authClient.emailOtp.verifyEmail()` - Verify OTP and create session
- `authClient.emailOtp.sendVerificationOtp()` - Resend OTP

**Session Storage:**
- Stores signup data (firstName, lastName) temporarily
- Cleared after successful verification
- Used to update user profile after account creation

## API Integration

### Better Auth Endpoints Used

All endpoints are auto-generated by Better Auth on the backend:

**Sign-Up Flow:**
```
POST /api/auth/email-otp/send-verification-otp
  Body: { email, type: "email-verification" }
  Response: { success: true }

POST /api/auth/email-otp/verify-email
  Body: { email, otp }
  Response: { user, session }
```

**Sign-In Flow:**
```
POST /api/auth/email-otp/send-verification-otp
  Body: { email, type: "sign-in" }
  Response: { success: true }

POST /api/auth/email-otp/verify-email
  Body: { email, otp }
  Response: { user, session }
```

**Google OAuth:**
```
GET /api/auth/sign-in/google
  Redirects to Google OAuth consent screen

GET /api/auth/callback/google
  Handles OAuth callback, creates session
```

**Session Management:**
```
GET /api/auth/session
  Response: { user, session } or null

POST /api/auth/sign-out
  Clears session cookie
```

## Type Safety

### User Type Mapping

Better Auth's user type doesn't include our custom schema fields. We handle this by:

```typescript
// Cast to any to access custom fields
const betterAuthUser = session?.user as any;

// Map to application's User type
const user: User = {
  id: betterAuthUser.id,
  firstName: betterAuthUser.firstName ?? betterAuthUser.name?.split(" ")[0],
  lastName: betterAuthUser.lastName ?? betterAuthUser.name?.split(" ")[1],
  email: betterAuthUser.email,
  emailVerified: betterAuthUser.emailVerified,
  avatarUrl: betterAuthUser.image,
  language: betterAuthUser.language ?? "en",
  dataRetentionDays: betterAuthUser.dataRetentionDays ?? 30,
  // ... other fields
};
```

**Note:** Custom fields (firstName, lastName, language, etc.) are stored in the database but may not be immediately available in the session. We'll need to fetch the complete profile from `/home/profile` endpoint.

## Troubleshooting

### Issue: "Property 'emailOtp' does not exist"
**Cause:** Email OTP plugin not configured in client
**Fix:** Add `emailOTPClient()` to client plugins array

### Issue: Session not persisting
**Cause:** Backend cookie configuration or CORS
**Fix:**
1. Check backend CORS allows credentials
2. Verify cookie domain/path settings
3. Check browser cookie storage

### Issue: Google OAuth redirect fails
**Cause:** Redirect URI mismatch
**Fix:** Update Google Console redirect URI to:
- Dev: `http://localhost:3000/api/auth/callback/google`
- Prod: `https://yourdomain.com/api/auth/callback/google`

### Issue: OTP not received
**Cause:** Backend email service not configured
**Fix:** Check backend email service (Resend) configuration

### Issue: Type errors in auth-provider
**Cause:** Better Auth user type doesn't include custom fields
**Fix:** Use type assertion (`as any`) or extend Better Auth types
